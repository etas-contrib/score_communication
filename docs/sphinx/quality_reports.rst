Quality Reports
===============

.. include:: quality_links.rst

Nightly quality job results are built and published to GitHub Pages after each
nightly run of the `Nightly Quality Jobs`_ workflow.

.. list-table::
   :widths: 20 45 35
   :header-rows: 1

   * - Job
     - Description
     - Report
   * - Coverage
     - Line, function, and branch coverage from C++ unit tests (gcov/lcov)
     - |coverage_report_link|
   * - Clang-Tidy
     - Static analysis findings (errors and warnings) across all C++ targets
     - |clang_tidy_report_link|
   * - CodeQL
     - MISRA C++ compliance findings via CodeQL (codeql/misra-cpp-coding-standards)
     - | |codeql_report_link|
       | |codeql_integrity_report_link|
       | |codeql_deviations_report_link|
       | |codeql_compliance_report_link|
       | |codeql_recat_report_link|

|quality_dashboard_link|

Local evidence targets
----------------------

The repository exposes stable Bazel entry points for the story's verification
artifacts. On Linux x86-64 their outputs are:

.. list-table::
   :widths: 28 32 40
   :header-rows: 1

   * - Evidence
     - Bazel target
     - Result
   * - Unit-test results
     - ``bazel run //:unit_test_results``
     - ``_quality/artifacts/tests.unit.linux_x86_64.xml`` and
       ``_quality/artifacts/tests.unit.linux_x86_64.manifest.json``
   * - Component-test results
     - ``bazel run //:component_test_results``
     - ``_quality/artifacts/tests.component.linux_x86_64.xml`` and
       ``_quality/artifacts/tests.component.linux_x86_64.manifest.json``
   * - C++ coverage
     - ``bazel run //:code_coverage``
     - ``_quality/artifacts/coverage/cpp/linux_x86_64/`` and
       ``_quality/artifacts/coverage.cpp.linux_x86_64.{zip,manifest.json}``
   * - Requirements and traceability metrics
     - ``bazel run //:docs_check``
     - ``_build/needs.json`` and ``_build/metrics.json``

The traceability command reuses the requirements discovered by the existing
``//docs/sphinx:sphinx_doc_needs`` target and enriches them with test links
from available Bazel JUnit XML. ``metrics.json`` is not a replacement for the
JUnit and coverage artifacts. Other platforms use their own
``<operating-system>_<architecture>`` variant in the filenames.

.. note::

   Quality reports are generated by the nightly CI job and published
   exclusively alongside the ``latest`` documentation on GitHub Pages.
   In local Sphinx builds the link cells above show equivalent ``bazel run``
   commands. In versioned release docs, every quality link (coverage,
   dashboard, clang-tidy, and CodeQL) points to the corresponding report
   uploaded as a release artifact for that release.

.. _Nightly Quality Jobs: https://github.com/eclipse-score/communication/actions/workflows/nightly_quality.yml
